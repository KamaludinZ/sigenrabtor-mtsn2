# SIRABTOR v1.0.0 — MTsN 2 Kota Malang

Generator KAK/TOR & RAB madrasah. PRD lengkap: `npx ngodingpakeai plan get fe0f436c-8f4b-4ce7-92bf-510b53eb56e7`.

Nama & versi tampilan diatur di `config/sigenrabtor.php` (`aplikasi.nama`, `aplikasi.versi`). Nama database, volume Docker, dan repositori tetap `sigenrabtor` (identitas teknis, tidak tampil ke pengguna).

## Stack
- PHP 8.4, Laravel 13, Livewire 4 (komponen berbasis kelas di `app/Livewire`, view di `resources/views/livewire`), Alpine.js (bawaan Livewire), Tailwind CSS 4, Vite.
- PostgreSQL 18 via Docker: `docker compose up -d` (port 5434, DB `sigenrabtor`; tes memakai `sigenrabtor_testing`).

## Perintah
- Jalankan: `php artisan serve` + `npm run dev` (atau `npm run build`).
- Tes: `php artisan test` · E2E: `npm run test:e2e` (Playwright, channel chrome, server port 8010) · Format: `vendor/bin/pint`.

## Konvensi
- Bahasa UI & domain: Indonesia (nama tabel/kolom mengikuti PRD: `activities`, `anggaran_kegiatan`, `budget_items`, ...).
- Frontend-first: layar dibangun di atas `App\Support\Stub\StubData` lalu backend menggantinya dengan Eloquent tanpa mengubah bentuk data di view.
- Penyimpanan kegiatan lewat kontrak `App\Contracts\KegiatanRepository` (saat ini `StubKegiatanRepository`, berkas JSON di disk local; E2E memakai `stub/kegiatan-e2e.json`). Backend cukup mengganti binding di `AppServiceProvider`.
- Master kode per tahun anggaran lewat fasad `App\Support\MasterKode` (kontrak `MasterKodeRepository`; tiruan: `app/Support/Stub/data/master-{tahun}.php`, 2025 fiktif). Jangan hardcode jumlah/isi kode — berubah tiap tahun & berasal dari unggahan Excel.
- Komponen UI Blade di `resources/views/components/ui` (`<x-ui.icon>`, `<x-ui.form-section>`, `<x-ui.status-badge>`, `<x-ui.toast>`).
- Livewire 4: `wire:model.blur` hanya menunda state klien (tanpa request). Untuk validasi saat blur pakai `wire:model.live.blur`.
- Blade: jangan campur `@php(...)` bentuk pendek dengan blok `@php … @endphp` dalam satu file (kompilasi Blade jadi salah); pakai satu bentuk saja.
- Livewire mengisi otomatis properti publik yang namanya sama dengan parameter rute (mis. `{kegiatan}`); beri nama lain untuk properti data (mis. `$dataKegiatan`).
- E2E seret-lepas: gulir dengan `behavior: 'instant'` (CSS memakai `scroll-behavior: smooth`) dan bidik ulang sasaran selama menyeret; pilih elemen lewat label/test-id, bukan selektor atribut ber-backslash.
- Uang: PHP `Format::rupiah()`/`angka()`/`rupiahDokumen()` ("Rp10.000.000,-"), Blade `<x-ui.uang :nilai>`, input `<x-ui.rupiah>` (pagu sumber dana: `<x-kegiatan.input-pagu :jenis>` — aktif bila sumbernya dicentang, status batas pagu dihitung ulang tiap ketukan; ringkasan/kelengkapan pagu di klien lewat Alpine `paguKegiatan`, resources/js/pagu-kegiatan.js); klien `$rupiah`/`$angka`/`$jumlahRab`/`$terbilang`/`$statusPagu` (resources/js/format.js, kembaran server; kasus bersama di `tests/fixtures/`). Terbilang: `App\Support\Terbilang::rupiah()`. Hitung RAB hanya lewat `KalkulatorRab`. Tanggal terbaca: `Format::tanggalPanjang()`/`akhirPekan()` ↔ klien `$tanggalPanjang`/`$akhirPekan` (tanpa locale browser; kasus `tests/fixtures/tanggal.json`).
- Anggaran per sumber dana: `App\Support\Rab\AnggaranKegiatan::untuk($kegiatan)` → `AnggaranSumber` (pagu, total, terbilang, status pagu, termin); `RabRepository` menyimpan rincian + termin per kegiatan × sumber. Contoh tiruan: kegiatan 1 (Komite sesuai pagu, dua termin), 2 (DIPA sisa pagu + Komite sesuai), 3 (Komite melebihi pagu + DIPA pagu belum diisi); kondisi & kasus batas pagu di `StubBatasPagu` (kasusnya juga di `tests/fixtures/status-pagu.json`). Di tes pakai `$this->idKegiatanBaru()`/`jumlahContohKegiatan()`, jangan menulis id kegiatan baru.
- Sumber dana: enum `App\Enums\SumberDana` (urutan, kunci, keterangan, sebutan dokumen "DIPA MTsN 2 Kota Malang Tahun 2026", warna) dengan lencana `<x-rab.lencana-sumber :sumber awalan="RAB">`; status pagu hanya lewat `App\Support\Rab\StatusPagu` (`$anggaran->keteranganPagu()`) dan `<x-rab.status-pagu :status>` — teks baku "Sisa pagu Rp…"/"Melebihi pagu Rp…". Tabel halaman RAB "Pagu & RAB" (`?halaman=pagu`) lewat `App\Support\Rab\TabelPagu`: setiap RAB dibandingkan dengan pagunya sendiri, baris jumlah hanya ringkasan; persen pemakaian dibulatkan menjauhi 100 (100% hanya bila tepat pagu). Peringatan visual per RAB: `<x-rab.peringatan-pagu :sumber :hasil>` (isi dari `App\Support\Rab\PeringatanPagu`; tidak tampil bila tepat pagu); pratinjau KAK memakai `SusunanKak::$peringatanPagu` (penanda di Pembiayaan, cap DRAF selama melebihi pagu).
- Termin pembayaran: halaman `termin` di RAB (`Kegiatan\TerminPembayaran`, per sumber dana); status & blok dokumen "Mekanisme Pembayaran" (gaya `Rp…,00` seperti Form RAB) hanya lewat `App\Support\Rab\MekanismePembayaran`; kembaran klien `resources/js/termin.js` (`Alpine.data('jumlahTermin')`, jumlah/selisih/persen per ketukan; kasus bersama `tests/fixtures/status-termin.json`). Termin wajib pas (PRD aturan 6): `TerminPembayaran::pesanTidakPas()` menolak simpan termin dan `Form::terminTidakPas()` memblokir pengajuan (galat `form.termin_{sumber}`).
- Angka dokumen cetak (KAK Pembiayaan, header "Jumlah yang diajukan", Total keseluruhan RAB, variabel `${total}`/`${terbilang}`): selalu dari `App\Support\Dokumen\AngkaDokumen` (satu objek per kegiatan × sumber dana); `PemeriksaTerbilang` memeriksa pasangan "Rp… (terbilang)" di teks dokumen.
- Kalimat baku KAK (pelaksanaan, pelaporan, tempat, pembiayaan) hanya disusun lewat `App\Support\Kegiatan\KalimatKak`; pratinjau "Tercetak di KAK" di layar memakai fungsi yang sama. Kelompok isian dalam satu kartu: `<x-ui.sub-bagian huruf judul kelengkapan>`.
- State Pelaksanaan (jadwal, bulan, tempat, peserta, bentuk) dibaca lewat `App\Support\Kegiatan\DataPelaksanaan::dari($data)` (form: `$form->pelaksanaan()`) — tanggal selesai, kelengkapan, dan kalimat KAK diturunkan dari situ. Saran tempat/peserta: `SaranPelaksanaan` (riwayat `KegiatanRepository::riwayatIsian()` + `StubData::saranPelaksanaan()`).
- Livewire 4: ketikan yang belum selesai ikut terkirim bersama request kolom lain; bila server mengubah nilainya di hook `updated` (format/kapital), respons menimpa `$wire` dan ketikan terbaru hilang. Lakukan format yang sama di klien lewat `x-on:input.capture` agar normalisasi server tidak mengubah apa pun.
- Pilihan ganda yang diklik beruntun (mis. bulan pelaksanaan) dikelola Alpine (`Alpine.data('pemilihBulan')`, `resources/js/pemilih-bulan.js`): tampil seketika lalu `$wire.$set` mengirim array utuh yang sudah rapi, sehingga normalisasi server tidak mengubah apa pun.
- Impor Excel bertahap (PhpSpreadsheet): turunan `App\Livewire\Impor\ImporBertahap` + view `livewire.impor.bertahap` (Unggah → Periksa per baris siap/dilewati/gagal + alasan → Proses per 5 baris dengan bilah kemajuan → Laporan, bisa diunduh). Turunan cukup `periksaBerkas()` dan `simpanBaris()`. Tabel kegiatan `/kegiatan` (`Kegiatan\Daftar`: filter & urutan di URL, kondisi anggaran dari `AnggaranKegiatan`); impor kegiatan: (`Kegiatan\ImporKegiatan`, `App\Support\Kegiatan\Impor\*`); nama yang sudah ada dilewati sehingga berkas aman diimpor ulang. Blok yang berganti total antar-tahap diberi `wire:key` per tahap agar status Alpine lama (mis. `x-show`) tidak terbawa morph.
- Impor rincian RAB: `Kegiatan\ImporRab` (turunan ImporBertahap) + `App\Support\Rab\Impor\*`; tabel dicari dari judul kolom (`PembacaImporRab::JUDUL`), penyesuaian format di `PemeriksaImporRab`. Pembukaan berkas & sel bersama di `App\Support\Impor\LembarExcel` (CSV dibaca sebagai teks lewat StringValueBinder). Jangan menulis berkas proyek selama E2E berjalan: server PHP lokal melambat dan tes gagal.
- Konteks kegiatan: bahan AI hanya lewat `App\Support\Kegiatan\KonteksAi` (aspek, isian lain, redaksi NIP); kembaran klien `resources/js/konteks.js` (`Alpine.data('catatanKonteks')`: aspek & NIP per ketukan, draf lokal per kegiatan di localStorage yang dibuang saat event `kegiatan-tersimpan`/`konteks-tersimpan`). Kegiatan tersimpan menyimpan konteks otomatis (`$wire.$set` 2 detik setelah berhenti mengetik → `Form::simpanKonteksOtomatis`, hanya kolom konteks); karena itu konteks tidak dirapikan di tempat — spasinya dirapikan saat disimpan.
- Matrik & jadwal (PRD F10): halaman `Kegiatan\MatrikJadwal` (`/kegiatan/{id}/matrik`, tab ruang kerja "Matrik & Jadwal"); data hanya lewat `App\Support\Kegiatan\MatrikTahapan` (3 tahapan baku × bulan 1–12, butir baku dari template KAK) dan `JadwalKegiatan` (6 baris baku; waktu disimpan sebagai nomor bulan, tahunnya selalu tahun anggaran aktif — PRD aturan 3), tersimpan di data kegiatan kunci `matrik`/`jadwal`. Sel grid lewat Alpine `gridMatrik` (resources/js/matrik.js): klik/seret/keyboard hanya mengubah state lokal (`$wire.$set(..., false)`, tanpa request per sel) yang terkirim bersama aksi berikutnya (Simpan, Batalkan, isi otomatis → `updatedMatrik` merapikan & membatalkan Urungkan); ringkasan, kelengkapan, dan "Belum disimpan" dihitung di klien lewat `$ringkasanMatrik` (kembaran `MatrikTahapan::jumlahTanda()/lengkap()`, kasus `tests/fixtures/ringkasan-matrik.json`); grid dikunci selama aksi server yang menimpa matrik; pindah halaman lewat `wire:navigate` saat ada perubahan meminta konfirmasi (`livewire:navigate`). Sentuh & keyboard memakai event click agar geser tabel di layar sempit tidak menandai sel. Jadwal disunting sebagai baris {uraian, mulai, sampai} (uraian `wire:model.live.blur` tanpa dirapikan di tempat; `MatrikJadwal::jadwalUntukDisimpan()` merapikan uraian & mengubah mulai..sampai menjadi daftar bulan); baris bisa ditambah (maks. `JadwalKegiatan::MAKS_BARIS`, baris baru difokuskan lewat event `jadwal-ditambah`), dinaikkan/diturunkan (urutan = urutan cetak), dan dihapus (Urungkan lewat `jadwalSebelum`; galat baris dibuang `resetErrorJadwal()` karena terikat indeks) — jadwal kosong tersimpan apa adanya; satu tombol Simpan untuk matrik & jadwal. Konsistensi bulan (matrik/jadwal vs bulan pelaksanaan, batas laporan, dan satu sama lain): `App\Support\Kegiatan\KonsistensiBulan` (temuan peringatan/saran, tidak memblokir simpan) dengan kembaran klien `resources/js/konsistensi-bulan.js` (`Alpine.data('panelKonsistensi')`, pesan sama persis; kasus `tests/fixtures/konsistensi-bulan.json`); panel samping `wire:ignore` karena isinya dihitung Alpine dari state lokal. Contoh kegiatan 3 menyimpan matrik & jadwal yang sebagian tersalin (6 temuan). Usul jadwal AI: panel samping `usulTerbuka` (permintaan: acuan waktu, jenis kegiatan `KonteksAi::jenisKegiatan()`/`tebakJenis()`, instruksi → 2–3 versi) — selama AI belum tersambung versinya dari `StubUsulanJadwal::versi()` (6/5/4 baris, bulan dari acuan); `pakaiUsulan()` mengganti jadwal lewat `jadwalSebelum` (bisa diurungkan, tersimpan saat Simpan).
- Notifikasi dari Livewire: `$this->dispatch('notify', message: '...', type: 'success|error|info')`.
- Real-time antar-tab (tiruan): perubahan RAB/pagu men-dispatch `anggaran-berubah` (kegiatan) — Rab lewat tanda `AnggaranKegiatan::tanda()` di `rendering()`, Form saat simpan; `resources/js/siaran.js` menyiarkannya lewat BroadcastChannel menjadi event Livewire `anggaran-diperbarui` di tab lain (jangan disiarkan balik). State Alpine yang menyimpan total RAB diberi `wire:key` berisi totalnya agar dibuat ulang saat angka berubah.
- Menu samping: `App\Support\Navigation` — item otomatis aktif begitu rutenya terdaftar.
